# GuGu AI Visual Studio 3.0.0 验证记录

验证日期：2026-10-07

## 结论

局域网团队版的账号、权限、数据隔离、积分、管理员后台和原有创作功能已完成集成验证，可以进入公司局域网试运行。验证过程使用隔离的临时数据库与输出目录，没有创建或修改正式的 `data/team.db`，也没有覆盖现有 9 个角色项目。

## 本次升级覆盖

- 注册、登录、退出、14 天服务端会话和登录失败限流。
- 新账号默认待审核；管理员可审核、停用、重置密码和调整积分。
- 管理员独占接口设置、团队注册开关、8 类功能计费和操作审计。
- 任务提交时冻结积分，成功结算，失败或服务重启时释放。
- 任务、生成结果、写真、角色项目和浏览器 3D 工作区按用户隔离。
- 管理员可查看团队总览、各用户流水、调用记录、任务、内容清单和空间占用，并删除已完成或失败任务。
- 初始管理员继续使用升级前的角色项目、写真和输出目录；其他用户使用独立目录。
- API Key 仅保存在服务端配置中，不通过普通状态接口返回。
- 对跨站写请求校验 `Origin`；配置 `PUBLIC_ORIGIN` 后采用固定来源白名单。

## 自动化验证

### 主项目

命令：

```powershell
npm.cmd test
```

结果：55 / 55 通过。覆盖原有图片生成与编辑约束、历史文件、写真、3D、快速启动，以及新增的团队数据库与真实 HTTP 服务流程。

新增的服务流程测试实际验证了：

1. 健康检查允许匿名访问，其余业务 API 要求登录。
2. 管理员登录并获得 HttpOnly 会话 Cookie。
3. 同事注册后处于待审核状态，审核前不能登录。
4. 管理员查看用户内容、审核账号并分配积分。
5. 普通用户登录后只能访问个人数据，不能进入管理员接口或修改 API 设置。
6. 非信任来源的写请求返回 403。

## 上线前人工事项

1. 首次启动后保存启动窗口显示的随机管理员密码，并尽快在后台重置。
2. 在 `.env` 中设置固定的 `PUBLIC_ORIGIN`；如同时使用 IP 与内网域名，用英文逗号分隔。
3. 只在 Windows 防火墙“专用网络”开放 TCP 8797，不做公网端口映射。
4. 使用管理员账号配置团队 API Key，再用一个普通测试账号完成一次真实的小额生成。
5. 制定 `config/`、`data/`、`output/` 三个目录的停机备份计划。

付费生成没有纳入自动化测试，因此上游账户余额、模型权限、网络连通性和供应商响应仍需在实际部署环境中用一次小额任务确认。
